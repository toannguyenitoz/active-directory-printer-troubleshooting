## ✅ Contribution Guidelines

1. Create a focused branch for one improvement.
2. Keep examples safe for enterprise environments.
3. Use generic server names, IP addresses and user details.
4. Add `SupportsShouldProcess` to scripts that make changes.
5. Include comment-based help and practical examples.
6. Test Markdown links and PowerShell syntax before submitting.
7. Explain the problem, solution, validation and rollback approach.

## 🧪 PowerShell Quality Checklist

- Use approved verbs.
- Validate parameters.
- Provide meaningful errors.
- Avoid silently deleting queues, ports, drivers or jobs.
- Support `-WhatIf` for destructive operations.
- Do not include credentials, production addresses or confidential data.

## 📝 Documentation Style

Use clear headings, short procedures, tables for comparisons, PowerShell code blocks and GitHub callouts such as `NOTE`, `TIP`, `IMPORTANT`, `WARNING` and `CAUTION`.
